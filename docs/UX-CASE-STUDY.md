# Packeta — UX Case Study

## A clearer journey from checkout to collection

**Independent concept by Sabnam Pariyar.**

### Project brief

Parcel delivery includes a series of small decisions: checking progress, choosing where to collect, understanding a notification, or arranging a return. My design question was: **how might we make the next useful action obvious at every stage of a parcel journey?**

Packeta is an existing Czech logistics company. This study explores a fictional alternative interface; it is not a commissioned redesign.

### The problem hypothesis

Users may feel uncertainty when a delivery status does not clearly explain what happens next. Pickup-point comparison and returns can add cognitive steps, particularly for first-time customers.

These are **design hypotheses**, not claims about measured faults in Packeta's current product.

### Goals

1. Make shipment progress understandable at a glance.
2. Connect status changes to useful contextual actions.
3. Help people compare pickup options without unnecessary complexity.
4. Present returns as short, reassuring steps.
5. Establish accessible reusable interface patterns.

### Three flows

**Track:** Open a shipment → understand its timeline → inspect the next action → simulate arrival.

**Choose pickup:** Scan illustrative pickup map → compare available options → select preferred location.

**Return:** Start return → enter fictional return code → read simple handover instructions.

### Design decisions

- A dark, high-contrast hero introduces the concept without distracting from the product itself.
- Action red is deliberately limited to priority actions and progress.
- White cards on warm-neutral canvas organize related information.
- Status badges pair words with color to avoid communicating through color alone.
- A single dominant action is used in each focused context.
- Mobile navigation stays visible for quick switching between the prototype and design study.

### Prototype boundaries

All parcels, codes, locations and status updates are sample data. The stylized map is not geospatially accurate, and no API calls are made to Packeta. External photography is moodboard inspiration.

### Research and validation plan

The next iteration could include:

- Five to seven short moderated usability sessions.
- First-time tracking and pickup-comparison tasks.
- Assessment of task success, completion time and error recovery.
- Keyboard, screen-reader and contrast checks.
- Iteration based on observed confusion rather than assumptions.

No interviews, usability metrics or customer outcomes are claimed as completed.
